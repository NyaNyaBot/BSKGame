# 回合管理器

> **Status**: Approved
> **Author**: Sulequan + Agents
> **Last Updated**: 2026-04-27
> **Implements Pillar**: 精准即快感；小而精致；层层递进

## Summary

回合管理器是《回响之刃》战斗流程的时序中枢。它负责创建战斗上下文、推进玩家指令阶段、执行我方行动、调度敌方攻击阶段、拥有 `CombatClockMs`、冻结输入阶段、处理暂停/恢复、判定战斗胜负，并在场景卸载时清理战斗临时状态。它不计算伤害、不判定弹反结果、不选择 AI 行为细节，而是让这些系统在同一个确定的战斗节拍里协作。

> **Quick reference** — Layer: `Core` · Priority: `MVP` · Key deps: `输入系统`, `角色数据模型`, `场景管理`, `实时弹反系统`

## Overview

回合管理器把“指令选择 → 我方行动 → 敌方攻击读招 → 弹反判定 → 结算 → 下一轮”组织成可测试、可暂停、可回放的状态机。MVP 只支持 1 个玩家可控角色、若干敌人、1 个 active 敌方攻击段和 1 个 counter window，但接口必须能扩展到三人小队、多敌攻击模式、技能系统和 Boss 阶段。所有战斗内逻辑时间统一由回合管理器拥有的 `CombatClockMs` 推进；输入、弹反、AI、UI、音频和反馈只能读取该时钟或请求暂停，不能各自推进战斗时间。

## Player Fantasy

玩家不应该感觉战斗是在一堆系统抢着结算，而应该感觉每个回合都像钟楼齿轮一样精密：自己先做策略选择，敌人再清楚地露出攻击节奏，成功弹反后战斗节拍立刻为玩家让出反击空间。回合管理器服务“精准即快感”和“层层递进”：它把纯策略的冷静思考和实时弹反的瞬间紧张接在一起，让玩家相信自己读懂敌人的时机后，整个战斗流程都会尊重这个结果。

## Detailed Design

### Core Rules

1. **回合管理器拥有战斗流程，不拥有具体玩法计算。** 它决定当前阶段、当前行动者、敌方攻击段生命周期、胜负检查和暂停/恢复；伤害公式、AI 选择、技能效果、弹反判定由对应系统拥有。
2. **所有战斗时间使用 `CombatClockMs`。** `CombatClockMs` 是单调逻辑时间，单位 `long ms`；正常战斗推进时增加，暂停、系统菜单、平台后台和 hit stop 时停止。
3. **输入阶段必须显式。** 输入系统根据回合管理器发布的 `BattleInputPhase` 启用或禁用触区；非输入阶段不得生成战斗输入。
4. **MVP 只允许一个玩家行动者和一个 active 敌方攻击段。** 多玩家角色行动队列、多敌同步可弹反窗口和复杂 Boss 阶段属于扩展；MVP 中若出现第二个可弹反段，必须触发 `OverlapRejected` 流程。
5. **玩家指令阶段不计时。** MVP 默认无指令倒计时；玩家可冷静选择行动。实时压力只发生在敌方攻击读招和弹反窗口。
6. **敌方攻击段由回合管理器调度，攻击模式提供内容事实。** 敌人 AI / 攻击模式选择要执行的攻击，回合管理器为每个段分配 `attackSegmentId`、`timelineSequenceId`、`sceneContextId` 和生命周期事件。
7. **回合管理器必须兼容弹反契约。** 它必须提供结构完整的 `AttackSegmentTimelineSeed`，由实时弹反系统派生并冻结 `FrozenAttackSegmentTimeline`；回合管理器尊重 `ParryResolved`、`ParryCancelled`、`OverlapRejected`、`AttackSegmentTimelineRejected`、`CounterEntryOpened` 和 `CounterEntryClosed` 的事件顺序。
8. **Counter window 是战斗流程的一等状态。** `PerfectParry` 打开 counter window 后，普通回合推进暂停或中断；counter 被消耗、过期或取消后，回合管理器广播 `CounterEntryClosed` 并恢复合法流程。
9. **胜负判定只读取角色状态，不直接改 HP。** 回合管理器读取角色快照判断玩家全灭、敌人全灭或 Boss 阶段完成；HP 修改和死亡事件由伤害与生命系统拥有。
10. **场景上下文必须贯穿所有战斗事件。** 所有回合、攻击、输入、弹反、counter 和胜负事件必须携带 `sceneContextId + sceneVersion`，过期事件不得影响当前战斗。
11. **战斗流程必须可确定性回放。** 同一战斗配置、角色快照、AI 选择序列和输入时间戳应产生同样的阶段事件顺序。
12. **MVP 不实现失败行动延迟。** 概念文档提到失败弹反可能延迟下回合行动；MVP 先不实现，以免和弹反核心验证耦合。该规则留给伤害与生命系统或技能系统后续定义。

### States and Transitions

| State | Entry Condition | Exit Condition | Behavior |
|---|---|---|---|
| `Uninitialized` | 无战斗上下文 | 场景管理请求创建战斗 | 不推进时钟，不接收输入 |
| `PreparingBattle` | 收到 `StartBattleRequest` | 角色实例、敌人配置、输入上下文准备完成 | 创建 `BattleContext`，绑定 `SceneContext`，初始化 `CombatClockMs=0` |
| `PlayerCommand` | 战斗开始或上一轮结束且玩家可行动 | 玩家提交合法行动，或战斗被暂停/取消 | 开启玩家指令输入；不推进敌方攻击时间轴 |
| `PlayerActionResolving` | 收到玩家行动请求 | 行动播放/效果完成，或取消 | 锁定玩家输入，广播行动开始/完成；技能系统后续接管具体效果 |
| `EnemyPlanning` | 玩家行动完成且仍有敌人可行动 | AI/攻击模式提交攻击计划 | 读取敌人快照，选择攻击模式；MVP 可使用脚本列表替代 AI |
| `EnemyAttackTelegraph` | 攻击段 seed 提交并通过基础校验 | 到达 `windowOpenMs`、攻击取消或 seed 被弹反系统拒绝 | 推进 `CombatClockMs`，广播 `EnemyWindUpStarted` 与 `AttackSegmentTimelineSeed`；若该段可弹反，发布 `BattleInputPhaseChanged(inputPhase=Parry)` |
| `EnemyAttackResolving` | 攻击段进入命中/结算流程 | `ParryResolved`、`ParryCancelled`、`AttackSegmentTimelineRejected`、攻击自然完成或目标无效 | 等待弹反、伤害和反馈完成；同段只允许一个结果 |
| `CounterWindow` | `PerfectParry` 后收到 `CounterEntryOpened` | 反击消耗、过期、攻击段取消或场景卸载 | 暂停或中断后续攻击段，移交 counter 输入优先级 |
| `RoundEnd` | 玩家和敌方本轮关键结算完成 | 胜负已判定或进入下一轮 | 检查胜负、清理临时段、递增 `roundIndex` |
| `Suspended` | 暂停菜单、平台后台、场景切换或 hit stop | 恢复、取消或卸载 | 停止 `CombatClockMs`；输入系统进入 `Suspended` |
| `BattleEnding` | 胜利、失败、退出或加载新场景 | 场景管理确认卸载或重试 | 广播结果，关闭输入，清理临时系统 |
| `Disposed` | 战斗上下文销毁 | 新战斗创建 | 不接受迟到事件；只保留历史日志 |

## Formulas

### Combat Clock Advance

The `combat_clock_advance` formula is defined as:

`next_combat_clock_ms = current_combat_clock_ms + delta_ms if !is_paused && battle_phase_allows_time_advance else current_combat_clock_ms`

**Variables:**
| Variable | Symbol | Type | Range | Description |
|---|---|---|---|---|
| 当前战斗时钟 | `current_combat_clock_ms` | long | `>= 0` | 当前 `CombatClockMs` |
| 推进量 | `delta_ms` | long | `0-1000` per tick | 战斗流程请求推进的毫秒数 |
| 是否暂停 | `is_paused` | bool | `true/false` | 暂停、hit stop、后台或场景切换 |
| 阶段允许推进 | `battle_phase_allows_time_advance` | bool | `true/false` | `EnemyAttackTelegraph / EnemyAttackResolving / PlayerActionResolving` 等允许推进 |

**Output Range:** `>= current_combat_clock_ms`；暂停期间保持不变。  
**Example:** `current=1000`、`delta=16`、未暂停且处于敌方攻击阶段，则输出 `1016`；若 hit stop 中则仍为 `1000`。

### Next Acting Side

The `next_acting_side` formula is defined as:

`next_acting_side = Player if any(player.can_act && player.current_hp > 0) && phase_after_round_end; else Enemy if any(enemy.current_hp > 0); else None`

**Variables:**
| Variable | Symbol | Type | Range | Description |
|---|---|---|---|---|
| 玩家可行动 | `player.can_act` | bool | `true/false` | 来自角色快照 |
| 玩家生命 | `player.current_hp` | int | `0-999` | 来自角色快照 |
| 敌人生命 | `enemy.current_hp` | int | `0-999` | 来自角色快照 |
| 是否轮末 | `phase_after_round_end` | bool | `true/false` | 当前是否准备进入下一轮行动 |

**Output Range:** `Player / Enemy / None`。MVP 使用固定“玩家先行动、敌人后行动”的一轮结构，不使用速度排序。  
**Example:** 玩家 HP > 0 且可行动，敌人仍存活，轮末后进入 `PlayerCommand`。

### Battle Result

The `battle_result` formula is defined as:

`battle_result = Defeat if alive_player_count == 0; else Victory if alive_enemy_count == 0; else InProgress`

**Variables:**
| Variable | Symbol | Type | Range | Description |
|---|---|---|---|---|
| 存活玩家数 | `alive_player_count` | int | `0-3` MVP `0-1` | HP > 0 且未 Removed 的玩家角色 |
| 存活敌人数 | `alive_enemy_count` | int | `0-20` | HP > 0 且未 Removed 的敌人/Boss |

**Output Range:** `InProgress / Victory / Defeat`。  
**Example:** MVP 单玩家 HP 为 0，敌人仍存活，则 `battle_result=Defeat`。

### Timeline Sequence Assignment

The `timeline_sequence_assignment` formula is defined as:

`timeline_sequence_id = previous_timeline_sequence_id + 1 if same_attack_segment_resubmitted else 1`

**Variables:**
| Variable | Symbol | Type | Range | Description |
|---|---|---|---|---|
| 上一次时间轴版本 | `previous_timeline_sequence_id` | int | `0-9999` | 同一攻击段最近一次提交版本 |
| 是否同段重提 | `same_attack_segment_resubmitted` | bool | `true/false` | 重排、取消后恢复、慢动作重建等 |

**Output Range:** `1-10000`；超过上限视为配置或循环错误。  
**Example:** `attackSegmentId=A1` 首次提交为 `1`，因 `OverlapRejected` 重排后仍使用 `A1` 则为 `2`。

### Counter Window Expiry

The `counter_window_expired` formula is defined as:

`counter_window_expired = CombatClock.NowMs >= counter_expires_at_ms`

**Variables:**
| Variable | Symbol | Type | Range | Description |
|---|---|---|---|---|
| 当前战斗时钟 | `CombatClock.NowMs` | long | `>= 0` | 回合管理器拥有 |
| 反击过期时间 | `counter_expires_at_ms` | long | `>= 0` | `CounterEntryOpened.expiresAtMs` |

**Output Range:** `true / false`。  
**Example:** `expiresAtMs=12000`，当前为 `12016`，则回合管理器广播 `CounterEntryClosed(reason=Expired)`。

## Edge Cases

- **If 场景上下文已过期**: 所有回合、输入、攻击和 counter 事件被拒绝，不改变当前战斗。
- **If 战斗创建时没有玩家角色或没有敌人**: `StartBattleRequest` 失败，场景管理不得进入 active battle。
- **If 玩家在非 `PlayerCommand` 阶段提交行动**: 输入被拒绝并记录 `InputPhaseMismatch`，不进入行动队列。
- **If 敌方攻击段 seed 缺少回合管理器必需字段**: 该段不进入 `EnemyAttackTelegraph`，记录 `AttackSegmentSeedRejected(validationError=MissingRequiredField)` 并取消该段；若 seed 结构完整但窗口派生失败，则由实时弹反系统广播 `AttackSegmentTimelineRejected`。
- **If 第二个可弹反攻击段在 active 段未结束前提交**: 回合管理器不把它转成必中攻击；广播或转发 `OverlapRejected`，该段必须取消或用新 `timelineSequenceId` 重排。
- **If `PerfectParry` 打开 counter window**: 回合管理器暂停 `CounterInsertOnPerfect` 后续段；`InterruptOnPerfect` 取消后续段；`ContinueAfterPerfect` 可继续但不得遮蔽下一段读招。
- **If counter 输入被消耗**: 回合管理器广播 `CounterEntryClosed(reason=Consumed)`，再恢复或结束敌方攻击流程。
- **If counter window 到期**: 广播 `CounterEntryClosed(reason=Expired)`，恢复按 `comboInterruptRule` 排队的后续段或进入轮末。
- **If 攻击段取消或防守目标无效**: 广播 `ParryCancelled` 或消费来自弹反系统的取消事件，清理 active segment，不制造 `FailedParry`。
- **If hit stop 发生时玩家触摸屏幕**: 输入系统处于当前阶段但 `CombatClockMs` 不推进；已结算段不接受新输入绑定。
- **If 平台后台或系统菜单打开**: 进入 `Suspended`，停止 `CombatClockMs`，输入系统进入 `Suspended`，恢复后不补发暂停期间输入。
- **If 伤害事件导致玩家和敌人在同一逻辑 tick 全灭**: MVP 默认 `Defeat` 优先，除非后续胜负规则 GDD 改写。
- **If 战斗结束时仍有 active attack segment 或 counter window**: 广播 `CounterEntryClosed(reason=BattleEnding)` 和 attack cancel 清理事件，再进入 `BattleEnding`。
- **If 迟到 `ParryResolved` 到达已 disposed 战斗**: 使用 `battleContextId + sceneContextId + sceneVersion` 拒绝，不触发伤害或反馈。
- **If AI 或攻击模式无法提供下一段攻击**: 记录 `EnemyActionUnavailable`，MVP 可跳过敌方行动并进入 `RoundEnd`，但必须暴露为配置风险。

| 敌人 AI 与攻击模式 | Downstream / Peer | Hard | 选择攻击计划、提供攻击段内容事实、响应 counter 规则 |
| 技能与行动系统 | Downstream | Hard for full MVP combat | 执行玩家行动和 counter 行动；MVP 可用基础攻击替代 |
| 战斗 UI | Downstream | Hard for MVP validation | 显示当前阶段、可行动状态、胜负、暂停/重试 |
| 战斗反馈系统 | Downstream | Hard for parry validation | 请求 hit stop、反馈阶段和攻击事件 |
| 音频管理 | Downstream | Soft for MVP, Hard for polish | 切换战斗音乐、攻击 cue、胜负 cue |
| 教程引导 | Downstream | Soft / Alpha | 读取阶段并注入教学脚本，不改变正式语义 |

### Dependency Assumptions

- 伤害与生命系统 GDD 已批准；死亡事件、伤害幂等、同 tick 全灭时的 Defeat 优先已对齐。
- 敌人 AI 与攻击模式 GDD 已批准；攻击模式提交 `AttackSegmentTimelineSeed` 内容事实，回合管理器保留调度事实。
- 技能与行动系统 GDD 已批准；MVP 使用 `BasicAttackAction` 和 `CounterAction` 测试回合流程。
- 回合管理器必须保持纯 gameplay 逻辑可测；Unity 表现、协程、Animator 和 UI 不应成为流程状态的事实来源。

## Tuning Knobs

| Parameter | Current Value | Safe Range | Effect of Increase | Effect of Decrease |
|---|---:|---:|---|---|
| `counter_window_ms` | `900ms` provisional | `500-1500ms` | 反击更宽容，Perfect 后更容易接上 | 更强调熟练度，但可能错过爽点 |
| `enemy_action_gap_ms` | `300ms` provisional | `100-800ms` | 敌人行动间更可读 | 战斗节奏更快，读招更紧 |
| `round_end_delay_ms` | `250ms` provisional | `0-600ms` | 结算更清楚 | 下一轮更快 |
| `hit_stop_max_ms` | `130ms` | `50-160ms` | 允许更强冲击 | 反馈更克制 |
| `max_attack_segments_per_enemy_turn` | `3` | `1-6` | 支持更复杂连击 | MVP 更简单 |
| `max_rounds_per_battle` | `20` debug guard | `5-99` | 容忍长战斗 | 更早暴露死循环 |
| `combat_clock_tick_budget_ms` | `33ms` | `16-66ms` | 低帧率更宽容 | 更早发现卡顿 |
| `battle_event_log_capacity` | `256` | `128-1024` | 更易调试长战斗 | 内存更低 |

调参优先级：先锁定 `counter_window_ms`、`enemy_action_gap_ms` 和 `round_end_delay_ms`，因为它们决定战斗节奏；再调整 hit stop 上限和日志容量；最后处理多段攻击上限。

## Visual/Audio Requirements

回合管理器本身不播放高强度表现，但必须向表现层提供稳定、去重、带上下文的阶段事件。它的视觉/音频要求是“让别的系统知道何时表现”，而不是直接决定表现内容。

| Event | Visual Feedback | Audio Feedback | Priority |
|---|---|---|---|
| `BattleStarted` | 战斗 HUD 淡入，角色/敌人进入战斗站位 | 战斗音乐或环境层切换 | High |
| `BattlePhaseChanged(PlayerCommand)` | 行动按钮/可控角色高亮 | 轻 UI cue，可选 | High |
| `EnemyAttackPhaseStarted` | 焦点转向敌人，压低非关键 UI | 攻击前环境压缩或短 cue | High |
| `CounterEntryOpened` | 反击入口可用态，由弹反/UI 系统表现 | 上扬提示由弹反/音频系统表现 | Critical |
| `CounterEntryClosed` | 关闭反击可用态，恢复战斗 HUD | 过期/消耗 cue 可不同 | High |
| `BattleSuspended` | HUD 冻结或暂停 overlay | 音频 duck / pause | High |
| `BattleEnded` | 胜利/失败/重试入口 | 胜负 cue | Critical |

## UI Requirements

回合管理器需要战斗 HUD 和调试 UI 能读取以下信息：

| Information | Display Location | Update Frequency | Condition |
|---|---|---|---|
| 当前战斗阶段 | 战斗 HUD / debug overlay | `BattlePhaseChanged` | 战斗中 |
| 当前行动者 | 角色框、行动按钮、debug overlay | 行动者变化时 | `PlayerCommand` / `PlayerActionResolving` / `EnemyAttack*` |
| 输入阶段 | Debug overlay；正式 HUD 间接体现 | `BattleInputPhaseChanged` | QA / 开发构建 |
| 当前轮次 | Debug overlay；正式 UI 可隐藏 | `RoundEnd` | QA / 开发构建 |
| 暂停状态 | 暂停菜单/overlay | 暂停/恢复 | `Suspended` |
| Counter window 剩余时间 | MVP 正式 UI 不显示倒计时；debug overlay 可显示 | Counter 打开期间 | QA / 调参 |
| 胜利/失败/重试 | 战斗结束 UI | `BattleEnded` | 战斗结束 |

正式 HUD 不应显示精确敌方弹反窗口倒计时。回合管理器可以提供 debug 时间，但正式战斗读招仍由敌人动画、音频和弹反反馈承担。

## Acceptance Criteria

### Battle Flow Tests

- **GIVEN** 有效 `SceneContext`、玩家实例和敌人实例，**WHEN** 场景管理请求开始战斗，**THEN** 回合管理器创建 `BattleContext`，初始化 `roundIndex=1`、`CombatClockMs=0`，并进入 `PlayerCommand`。
- **GIVEN** 战斗处于 `PlayerCommand`，**WHEN** 玩家提交合法行动，**THEN** 回合管理器进入 `PlayerActionResolving`，广播 `BattleInputPhaseChanged(inputPhase=None)`。
- **GIVEN** 玩家行动完成且敌人仍存活，**WHEN** 回合管理器进入敌方流程，**THEN** 先进入 `EnemyPlanning`，再提交至少一个 `AttackSegmentTimelineSeed` 或记录 `EnemyActionUnavailable`。
- **GIVEN** 敌方攻击段开始，**WHEN** seed 通过回合管理器基础校验，**THEN** 事件携带 `sceneContextId`、`sceneVersion`、`battleContextId`、`attackSegmentId` 和 `timelineSequenceId`，并交由实时弹反系统执行冻结时间轴验证。
- **GIVEN** 可弹反敌方攻击段进入读招/窗口流程，**WHEN** 回合管理器进入 `EnemyAttackTelegraph`，**THEN** 输入系统收到 `BattleInputPhaseChanged(inputPhase=Parry)`；攻击段结束、取消或结算后恢复为 `None` 或下一合法阶段。
- **GIVEN** 本轮敌方行动和所有 pending counter/attack segment 完成，**WHEN** 胜负仍为 `InProgress`，**THEN** 回合管理器进入 `RoundEnd` 后递增 `roundIndex` 并回到 `PlayerCommand`。

### Clock and Pause Tests

- **GIVEN** 战斗处于 `EnemyAttackTelegraph` 且未暂停，**WHEN** `Advance(16)` 被调用，**THEN** `CombatClockMs` 增加 16。
- **GIVEN** 战斗处于 `PlayerCommand`，**WHEN** 玩家停留 10 秒真实时间不操作，**THEN** 敌方攻击段不推进，且不会凭现实时间错过弹反窗口。
- **GIVEN** hit stop 请求 `BeginHitStop(90, resolutionId)`，**WHEN** hit stop 活跃，**THEN** `CombatClockMs` 停止推进，已结算弹反不重算。
- **GIVEN** 暂停菜单、平台后台或场景切换发生，**WHEN** 回合管理器进入 `Suspended`，**THEN** 输入系统收到 `inputPhase=Suspended`，暂停期间输入不补发。
- **GIVEN** 恢复战斗，**WHEN** `Resume(reason)` 被调用，**THEN** `CombatClockMs` 从暂停前的值继续推进，不跳过未完成窗口。

### Parry and Counter Contract Tests

- **GIVEN** 攻击模式提交同一 `attackSegmentId` 的重排 seed，**WHEN** 回合管理器再次提交该段，**THEN** `timelineSequenceId = previous + 1`。
- **GIVEN** 第二个可弹反攻击段与 active 段重叠，**WHEN** 编排层提交它，**THEN** 回合管理器触发或转发 `OverlapRejected`，不得把该段转为不可弹反必中。
- **GIVEN** 实时弹反系统返回 `AttackSegmentTimelineRejected`，**WHEN** 回合管理器收到该事件，**THEN** 取消该攻击段、清理 active segment，并不得提交伤害或 `FailedParry`。
- **GIVEN** `ParryResolved(PerfectParry)` 且 `comboInterruptRule=CounterInsertOnPerfect`，**WHEN** `CounterEntryOpened` 触发，**THEN** 回合管理器进入 `CounterWindow` 并暂停后续段命中玩家。
- **GIVEN** counter 被玩家消耗，**WHEN** 反击系统通知完成，**THEN** 回合管理器广播 `CounterEntryClosed(reason=Consumed)`，随后恢复或结束敌方流程。
- **GIVEN** counter 到达 `expiresAtMs`，**WHEN** 未被消耗，**THEN** 回合管理器广播 `CounterEntryClosed(reason=Expired)` 且只广播一次。
- **GIVEN** 攻击段取消或目标无效，**WHEN** 取消发生在弹反结果前，**THEN** 回合管理器清理 active segment，不制造 `FailedParry`。

### Scene, Character, and Result Tests

- **GIVEN** 任意战斗事件携带旧 `sceneContextId` 或 `sceneVersion`，**WHEN** 当前场景已切换，**THEN** 回合管理器拒绝事件，不改变当前战斗。
- **GIVEN** 角色数据模型报告玩家 `CurrentHp=0` 且无其他存活玩家，**WHEN** 回合管理器执行胜负检查，**THEN** `battle_result=Defeat`。
- **GIVEN** 所有敌人 `CurrentHp=0`，**WHEN** 回合管理器执行胜负检查，**THEN** `battle_result=Victory`。
- **GIVEN** 玩家和敌人在同一逻辑 tick 全灭，**WHEN** MVP 胜负公式执行，**THEN** `Defeat` 优先，并记录 `SimultaneousDefeatPriority`。
- **GIVEN** 战斗结束或场景卸载，**WHEN** 回合管理器进入 `BattleEnding`，**THEN** active attack segment、counter window、输入阶段和临时订阅全部清理。

### Observability Tests

- **GIVEN** 连续执行 100 场短战斗自动化测试，**WHEN** 每场走完开始、玩家行动、敌方攻击、弹反/无弹反、胜负或下一轮，**THEN** 阶段事件顺序 deterministic，`CombatClockMs` 单调不倒退，迟到事件不会污染下一场。
- **GIVEN** 低帧率 15 / 20 / 30 FPS 测试环境，**WHEN** 敌方攻击段推进，**THEN** 攻击段事件按 `CombatClockMs` 触发，不使用处理帧时间替代逻辑时间。
- **GIVEN** 开发构建，**WHEN** 战斗运行，**THEN** event log 至少记录 `battleContextId`、`sceneContextId`、`phase`、`CombatClockMs`、`activeActorId`、`attackSegmentId`、`timelineSequenceId` 和 counter close reason。
