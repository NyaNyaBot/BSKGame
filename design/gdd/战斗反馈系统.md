# 战斗反馈系统

> **Status**: Approved
> **Author**: Sulequan + Agents
> **Last Updated**: 2026-04-27
> **Implements Pillar**: 精准即快感；小而精致；层层递进

## Summary

战斗反馈系统负责把战斗事件转化为动画、VFX、相机、震动、短顿帧和轻量音频 cue 请求。它让读招、弹反、受击、死亡和反击在触屏上“可读且爽”，但它不拥有任何玩法事实：不判定弹反、不修改 HP、不推进 `CombatClockMs`、不决定回合阶段。MVP 的核心目标是让 `PerfectParry`、`NormalParry`、`FailedParry` 和 `CounterAction` 有清晰差异，并在微信 WebGL 性能预算内稳定运行。

> **Quick reference** — Layer: `Presentation` · Priority: `MVP` · Key deps: `实时弹反系统`, `伤害与生命系统`, `回合管理器`, `敌人 AI 与攻击模式`, `技能与行动系统`

## Overview

反馈系统订阅战斗事件，查表选择反馈 profile，并向 Unity 表现层播放对应内容。它可以向回合管理器请求 hit stop，但最终是否暂停 `CombatClockMs` 由回合管理器裁决。所有反馈必须可降级：低端设备可减少粒子、震屏和重叠特效，但不能改变判定结果、伤害数值或事件顺序。

## Player Fantasy

玩家的手指按准时，世界应该短暂承认这件事：刀刃相撞、敌人动作被打断、画面一顿、金属爆响，随后出现反击机会。普通弹反应该让玩家知道“挡住了但不完美”；失败则清楚表达受击代价。反馈系统把规则翻译成身体感受。

## Detailed Design

### Core Rules

1. **反馈只消费事件。** 输入、弹反、伤害、行动、回合事件是事实来源。
2. **反馈不得改变结果。** 不得因为动画没播完、VFX 掉帧或音频延迟重算弹反/伤害。
3. **hit stop 是请求，不是直接控制。** 反馈系统发出 `HitStopRequest`，回合管理器裁决并控制 `CombatClockMs`。
4. **Perfect 是最高反馈强度。** 只有 `PerfectParry` 可以使用强金属爆响、金/橙高亮、短顿帧和明显震动。
5. **Normal 和 Failed 必须可区分。** Normal 用冷白短闪和轻受击；Failed 用受击/红色冲击和完整伤害反馈。
6. **读招优先于 UI 倒计时。** 敌人前摇动画、音频蓄压和轻视觉 cue 是玩家读窗口的主要来源。
7. **性能预算一等约束。** MVP 默认移动 WebGL：无 GC 尖峰、粒子数量和屏幕特效可降级。
8. **反馈幂等。** 同一 `resolutionId`、`damageRequestId` 或 `actionRequestId` 不重复播放关键反馈。
9. **迟到事件必须过滤。** 所有反馈事件校验 `sceneContextId + sceneVersion`。

### States and Transitions

| State | Entry Condition | Exit Condition | Behavior |
|---|---|---|---|
| `Idle` | 无战斗反馈待播 | 收到战斗事件 | 不占用预算 |
| `TelegraphCueActive` | `EnemyWindUpStarted` | 段取消、命中或结算 | 播放读招 cue |
| `ParryImpact` | `ParryResolved` | impact profile 完成 | 播放 Perfect/Normal/Failed 差异反馈 |
| `DamageImpact` | `DamageApplied` | 受击反馈完成 | 播放扣血、无伤、死亡前置反馈 |
| `CounterFeedback` | `CounterActionStarted` | counter commit/complete | 播放反击表现 |
| `Degraded` | 性能预算超限 | 预算恢复或战斗结束 | 降低特效强度 |
| `Disposed` | 场景卸载 | 新场景初始化 | 停止 pending 反馈 |

## Formulas

### Feedback Intensity

The `feedback_intensity` formula is defined as:

`feedback_intensity = Critical if parry_grade == PerfectParry; High if action_kind == Counter; Medium if final_damage > 0; Low otherwise`

**Variables:**
| Variable | Symbol | Type | Range | Description |
|---|---|---|---|---|
| 弹反等级 | `parry_grade` | enum/null | Perfect/Normal/Failed | 弹反结果 |
| 行动类型 | `action_kind` | enum/null | Basic/Counter | 行动结果 |
| 最终伤害 | `final_damage` | int | `0-9999` | 伤害系统输出 |

**Output Range:** `Low / Medium / High / Critical`。  
**Example:** PerfectParry 总是 Critical，即使最终伤害为 0。

### Hit Stop Duration

The `hit_stop_duration_ms` formula is defined as:

`hit_stop_duration_ms = profile_duration_ms if quality_tier_allows_hit_stop else 0`

**Variables:**
| Variable | Symbol | Type | Range | Description |
|---|---|---|---|---|
| profile 时长 | `profile_duration_ms` | int | `0-160` | 配置 |
| 品质允许 | `quality_tier_allows_hit_stop` | bool | `true/false` | 设备质量层 |

**Output Range:** `0-160`。  
**Example:** Perfect profile 90ms，高质量允许则请求 90ms；低质量可请求 0ms。

## Edge Cases

- **If 同一 `resolutionId` 重复到达**: 关键反馈只播放一次。
- **If `DamageApplied(finalDamage=0)` 且来源 Perfect**: 不播放受击，播放无伤/弹反成功反馈。
- **If `ParryCancelled`**: 清除 telegraph，不播放 Failed。
- **If 场景卸载**: 停止 pending VFX/震动/camera shake。
- **If FPS 低于阈值**: 进入 `Degraded`，减少粒子、屏幕闪白和震动，不改变事件。
- **If hit stop 期间新输入到达**: 反馈系统不处理输入；输入和弹反系统按时钟规则处理。
- **If 音频管理未来接管 cue**: 本系统只发音频 cue request，不直接绑定最终 mixer 逻辑。

## UI Requirements

反馈不得依赖 HUD 显示精确窗口。UI 可显示最近结果、HP、counter 可用态，但读招必须在 HUD 关闭或遮挡时仍可通过敌人表现和音频理解。

## Acceptance Criteria

- **GIVEN** `ParryResolved(PerfectParry)`，**WHEN** 反馈系统处理事件，**THEN** 播放 Critical profile 并发送一次 `HitStopRequest`。
- **GIVEN** `ParryResolved(NormalParry)`，**WHEN** 处理事件，**THEN** 播放弱于 Perfect 的格挡反馈，不打开 counter 表现。
- **GIVEN** `ParryResolved(FailedParry)` + `DamageApplied`，**WHEN** 处理事件，**THEN** 播放失败受击反馈和 HP 扣减表现。
- **GIVEN** `ParryCancelled`，**WHEN** 段取消，**THEN** 清理读招 cue，不播放失败反馈。
- **GIVEN** 同一 `resolutionId` 重复到达，**WHEN** 处理第二次，**THEN** 不重复播放 Critical 反馈或 hit stop 请求。
- **GIVEN** 设备 FPS 低于阈值，**WHEN** 连续触发高强度反馈，**THEN** 系统进入降级模式且战斗结果不变。
- **GIVEN** HUD 关闭或被遮挡，**WHEN** 敌人攻击前摇发生，**THEN** 玩家仍可从敌人表现/音频辨识读招。
