# 输入系统

> **Status**: Approved
> **Author**: Sulequan + Agents
> **Last Updated**: 2026-04-27
> **Implements Pillar**: 精准即快感；小而精致

## Summary

输入系统负责把微信小游戏 / WebGL 移动端触摸转化为可被战斗系统稳定消费的游戏输入事件。MVP 最重要的职责是为实时弹反提供低歧义的 `ParryAttempt`：包含触区命中、去重、时间戳来源、`CombatClockMs` 映射和诊断字段，确保“玩家什么时候按下”可以被准确验证。

> **Quick reference** — Layer: `Foundation` · Priority: `MVP` · Key deps: `角色数据模型`

## Overview

输入系统是玩家和战斗逻辑之间的触摸适配层。它不决定弹反成功或失败，也不修改角色、伤害或回合状态；它只负责采集触摸、判断是否命中已注册输入区域、去除平台重复事件、映射时间戳，并向下游广播结构化输入事件。MVP 只支持单指触摸、单一弹反触区和基础 UI 按钮输入，不支持键盘、鼠标右键、手柄、多点组合手势、滑动弹反或长按弹反。

## Player Fantasy

玩家应该感觉“我按下去的那一刻就是系统听见我的那一刻”。输入系统本身不可见，但它决定弹反是否可信：不能因为微信容器、低帧率、UGUI `onClick` 或重复触摸事件让玩家觉得“我明明按准了却没算”。它服务“精准即快感”的基础公平性。

## Detailed Design

### Core Rules

1. **MVP 只接受 Touch / PointerDown。** 弹反判定输入必须来自触摸按下瞬间，不得使用 UGUI Button `onClick`、PointerUp 或 click 合成事件作为判定来源。
2. **所有输入事件必须结构化。** 输入系统输出 `InputEvent` 或专用 `ParryAttempt`，不得让下游直接读取 Unity UI 组件状态。
3. **同一真实触摸最多生成一次可消费输入。** 使用 `actorId + touchId + inputSequenceId + inputKind` 去重，避免 `touchstart/touchend/click` 合成重复。
4. **输入系统不判定弹反结果。** 它只判断触区命中、角色可控性、输入来源和时间戳；成功、普通、失败由实时弹反系统判定。
5. **触区注册由 UI / 战斗系统提供。** 输入系统维护可查询的 `InputHitAreaRegistry`，包含 `areaId`、类型、所属角色、屏幕矩形、优先级和启用状态。
6. **时间戳必须声明来源。** 每个 `ParryAttempt` 必须包含 `rawTimestampMs`、`receivedRealtimeMs`、`battleTimestampMs`、`timestampSource` 和 `latencyDiagnostics`。
7. **无可靠原始时间戳时必须降级显式标记。** 若平台不提供可校准时间戳，使用接收帧时间映射，并标记 `timestampSource = ReceivedFrameFallback`。
8. **输入区域不拥有玩法规则。** 触区能否显示、是否可按、是否处于 Recovery，由 UI/弹反/回合系统决定；输入系统只执行注册表当前状态。
9. **暂停和系统覆盖时屏蔽战斗输入。** 当战斗处于 `Suspended`、系统菜单覆盖或平台后台时，不生成战斗输入事件。
10. **MVP 不做输入预测。** 不提前推测玩家意图，不为了手感伪造时间戳；只允许可记录、可回放的时间映射。

### States and Transitions


| State              | Entry Condition     | Exit Condition | Behavior                           |
| ------------------ | ------------------- | -------------- | ---------------------------------- |
| `Inactive`         | 游戏未进入可输入场景或输入系统未初始化 | 场景输入上下文创建      | 不广播输入                              |
| `ExplorationInput` | 探索场景激活              | 进入战斗或暂停        | 只处理探索点击 / 移动输入；MVP 可占位             |
| `BattleInput`      | 战斗上下文激活             | 战斗结束、暂停、场景切换   | 接收战斗 UI、弹反触区和基础按钮                  |
| `ParryArmed`       | 弹反触区注册且启用           | 触区禁用、暂停、弹反段结束  | 监听单指 PointerDown，生成 `ParryAttempt` |
| `Suspended`        | 暂停、系统菜单、平台后台        | 恢复战斗上下文        | 不生成战斗输入，保留注册表                      |
| `Disposed`         | 场景卸载或战斗上下文销毁        | 新上下文初始化        | 清空注册表与去重缓存                         |

## Formulas

### Hit Area Contains

The `hit_area_contains` formula is defined as:

`hit_area_contains = position_x >= rect_x && position_x <= rect_x + rect_width && position_y >= rect_y && position_y <= rect_y + rect_height`

**Variables:**


| Variable | Symbol        | Type  | Range  | Description    |
| -------- | ------------- | ----- | ------ | -------------- |
| 输入 X     | `position_x`  | float | `>= 0` | dp / Canvas 坐标 |
| 输入 Y     | `position_y`  | float | `>= 0` | dp / Canvas 坐标 |
| 区域 X     | `rect_x`      | float | `>= 0` | 热区左下角或约定原点     |
| 区域 Y     | `rect_y`      | float | `>= 0` | 热区左下角或约定原点     |
| 区域宽度     | `rect_width`  | float | `>= 0` | 热区宽度           |
| 区域高度     | `rect_height` | float | `>= 0` | 热区高度           |


**Output Range:** `true / false`。边界按闭区间命中。  
**Example:** 触点 `x=100, y=100`，热区 `x=50, y=50, width=100, height=100`，命中为 `true`。

### Battle Timestamp Mapping

The `battle_timestamp_ms` formula is defined as:

`battle_timestamp_ms = combat_clock_now_ms - max(0, received_realtime_ms - raw_timestamp_ms - calibrated_bridge_offset_ms)`

**Variables:**


| Variable | Symbol                        | Type | Range   | Description                |
| -------- | ----------------------------- | ---- | ------- | -------------------------- |
| 当前战斗时钟   | `combat_clock_now_ms`         | long | `>= 0`  | `CombatClock.NowMs`        |
| 接收时间     | `received_realtime_ms`        | long | `>= 0`  | 输入适配层收到事件的 real-time       |
| 原始输入时间   | `raw_timestamp_ms`            | long | `>= 0`  | 平台触摸事件时间                   |
| 桥接校准偏移   | `calibrated_bridge_offset_ms` | int  | `0-120` | JS / WebGL / Unity 时间基准校准值 |


**Output Range:** `0` 到 `combat_clock_now_ms`；若平台无可靠 raw timestamp，则使用 `combat_clock_now_ms` 并标记 fallback。  
**Example:** `now=10000`，`received=5000`，`raw=4960`，`offset=10`，输入延迟估计为 `30ms`，`battle_timestamp_ms=9970`。

### Duplicate Input Key

The `duplicate_input_key` formula is defined as:

`duplicate_input_key = actorId + ":" + touchId + ":" + inputSequenceId + ":" + inputKind`

**Variables:**


| Variable | Symbol            | Type       | Range            | Description              |
| -------- | ----------------- | ---------- | ---------------- | ------------------------ |
| 角色 ID    | `actorId`         | string/int | valid id         | 输入归属角色                   |
| 触摸 ID    | `touchId`         | int/null   | platform-defined | 平台 touch id              |
| 输入序号     | `inputSequenceId` | int        | monotonic        | 输入系统递增序号                 |
| 输入类型     | `inputKind`       | enum       | known kind       | Parry / UI / Exploration |


**Output Range:** unique string key。  
**Example:** `Player01:7:128:Parry`。

## Edge Cases

- **If 触摸命中多个输入区域**: 选择最高 `priority` 的 enabled 区域；若该区域 `blocksUnderlying=true`，不再传给下层。
- **If 触摸位于热区边界**: 按闭区间命中。
- **If 触摸发生在暂停或系统菜单覆盖时**: 不生成战斗输入，记录 `ignoredReason=Suspended`。
- **If 角色不可控、已死亡或不属于玩家阵营**: 不生成可消费 `ParryAttempt`，记录 `ActorNotControllable`。
- **If 同一触摸产生多个平台事件**: 只保留第一条 PointerDown / touchstart 语义事件，后续记录 `Duplicate`。
- **If 平台不提供可靠 raw timestamp**: 使用 `ReceivedFrameFallback`，并在设备证据中标记该场景不能证明真实低帧率触摸时序。
- **If UI 触区更新版本后迟到输入引用旧版本**: 输入被拒绝，记录 `AreaVersionStale`。
- **If 弹反触区处于 Recovery 但 Counter 已打开**: 弹反触区不得吞掉 Counter 输入；输入系统按当前注册表的 `blocksUnderlying` 处理。
- **If 触区尺寸小于最小热区**: 注册失败并报告 UI 配置错误。
- **If 场景卸载时仍有输入缓存**: 清空去重缓存和 hit area registry，不向下游补发输入。

## Visual/Audio Requirements

输入系统本身不播放高强度反馈；它只允许轻量输入确认事件，最终反馈由弹反、UI、音频和战斗反馈系统拥有。


| Event                   | Visual Feedback        | Audio Feedback | Priority |
| ----------------------- | ---------------------- | -------------- | -------- |
| `InputAccepted`         | 1 帧局部触摸确认，可被结果反馈覆盖     | 极轻触摸音，可选       | Medium   |
| `InputRejected`         | 调试或教程中可显示简短原因；正式战斗默认克制 | 无或极轻禁用音        | Low      |
| `InputAreaRegistered`   | 调试 overlay 可显示触区矩形     | 无              | Low      |
| `TimestampFallbackUsed` | 调试面板警告                 | 无              | Low      |

## Acceptance Criteria

- **GIVEN** 玩家在弹反热区内触发 PointerDown，**WHEN** 输入系统处理事件，**THEN** 生成一次 `ParryAttempt`，且 `wasInHitArea=true`。
- **GIVEN** 玩家在弹反热区外触发 PointerDown，**WHEN** 输入系统处理事件，**THEN** 不生成可消费 `ParryAttempt`，并记录 `ignoredReason=OutsideHitArea`。
- **GIVEN** 同一真实触摸产生 `touchstart/touchend/click`，**WHEN** 输入系统去重，**THEN** 只生成一次可消费输入，后续事件记录 `Duplicate`。
- **GIVEN** 角色 `IsControllable=false` 或已 `Defeated`，**WHEN** 玩家点击其绑定触区，**THEN** 输入被拒绝并记录 `ActorNotControllable`。
- **GIVEN** 战斗处于 `Suspended`，**WHEN** 玩家点击任意战斗触区，**THEN** 不生成战斗输入并记录 `Suspended`。
- **GIVEN** 平台提供可靠 raw timestamp，**WHEN** 输入系统映射时间，**THEN** `battleTimestampMs` 按 `battle_timestamp_ms` 公式计算，且 `timestampSource != ReceivedFrameFallback`。
- **GIVEN** 平台不提供可靠 raw timestamp，**WHEN** 输入系统映射时间，**THEN** 使用 `CombatClock.NowMs`，标记 `timestampSource=ReceivedFrameFallback`。
- **GIVEN** 两个输入区域重叠，**WHEN** 触摸同时命中它们，**THEN** 只选择最高 priority 的 enabled 区域；若其 `blocksUnderlying=true`，下层不收到输入。
- **GIVEN** UI 更新触区并增加 `stateVersion`，**WHEN** 旧版本迟到输入到达，**THEN** 输入被拒绝并记录 `AreaVersionStale`。
- **GIVEN** 微信小游戏真机设备至少 2 台，**WHEN** 每台执行 30 次触区内、30 次触区外、30 次快速重复点击，**THEN** 触区内生成唯一输入、触区外不生成、重复点击不会产生多次同 touch 可消费输入。
- **GIVEN** 低帧率测试锁定 15 / 20 / 30 FPS，**WHEN** 通过 TestInjection 注入边界时间戳，**THEN** 输出 `battleTimestampMs` 与注入值一致，不使用处理帧时间覆盖。
- **GIVEN** 战斗场景卸载，**WHEN** 输入上下文进入 `Disposed`，**THEN** hit area registry、duplicate cache 和 queued input 全部清空。
