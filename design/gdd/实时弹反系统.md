## Summary

实时弹反系统是《回响之刃》的核心战斗判定机制：当敌方攻击进入前摇与命中窗口时，玩家通过触屏输入在正确时机触发弹反。系统根据输入时机将结果判定为 `PerfectParry`、`NormalParry` 或 `FailedParry`，并把结果交给伤害、反馈、UI、音频和后续奖励系统使用。

本系统不拥有 HP、不推进回合、不选择敌人攻击、不播放正式表现。它只拥有弹反窗口派生、输入时机判定、弹反结果事件、counter 入口开启和异常/取消事件。最终 HP 修改由伤害与生命系统拥有；攻击段调度由回合管理器拥有；触摸采样与时间戳映射由输入系统拥有；读招和结果反馈由战斗反馈系统与战斗 UI 消费事件后表现。

> **Quick reference** — Layer: `Feature` · Priority: `MVP` · Key deps: `输入系统`, `回合管理器`, `伤害与生命系统`, `敌人 AI 与攻击模式`, `战斗反馈系统`, `战斗 UI`

## Revision Decisions

- **MVP 定位**：只验证“触屏读招 → 时间戳判定 → 强反馈”的核心手感；三人队伍、全员完美弹反和完整回响经济属于后续 Vertical Slice。
- **结果价值**：`PerfectParry` 是唯一无伤、开启 counter 入口、推进核心回响意图的结果；`NormalParry` 默认 50% 伤害且不推进核心回响；`FailedParry` 承受完整伤害。
- **时间权威**：所有判定使用回合管理器拥有的 `CombatClockMs`；输入系统只负责把平台触摸时间映射到 `battleTimestampMs`。
- **时间轴所有权**：敌人攻击模式只提交 `AttackSegmentTimelineSeed` 内容事实；弹反系统派生并冻结 `FrozenAttackSegmentTimeline`。
- **事件权威入口**：生产回响入口只使用 `ParryResolved.echoIntent`；不广播独立 `EchoIntentRequested`。
- **Counter handoff**：MVP 使用唯一策略：`CounterEntryOpened` 后弹反触区释放 raycast，反击系统注册更高优先级 counter area。
- **多敌重叠**：MVP 严格禁止两个可弹反攻击段同时 active；后进入段触发 `OverlapRejected`，必须重排或取消，不得转为不可弹反必中。
- **跨场景 DTO**：所有弹反事件携带 `sceneContextId` 与 `sceneVersion`，用于拒绝迟到事件。

## Player Fantasy

玩家应该感觉自己是小队在钟楼废墟中的最后防线。敌人的攻击不是一段自动播放的结算动画，而是一场逼近的威胁：前摇、音效和画面节奏逐渐收紧，直到玩家在命中前的瞬间触屏弹反。完美弹反成立时，刀刃相撞、时间短暂停住、火花和金属声爆开，玩家会感到“我读懂了敌人的节奏，并把它变成了我们的反击”。

这个系统服务的不是单纯反应速度炫技，而是“精准即守护”的幻想：一次正确判断能保护角色、扭转攻防节奏，并让玩家相信团队能继续向钟楼深处前进。

## Detailed Design

### Core Rules

1. **弹反只在敌方攻击阶段开放。** 只有回合管理器发布 `BattleInputPhaseChanged(inputPhase=Parry)` 后，输入系统才启用弹反触区。
2. **MVP 只支持 1 个可控角色与 1 个 active 可弹反攻击段。** 多角色、多方向、多敌同步弹反属于后续扩展。
3. **每个攻击段最多产生一次弹反结果。** 同一 `attackSegmentId + timelineSequenceId` 只允许一个 `resolutionId` 生效。
4. **弹反系统只判定，不改 HP。** 它输出 `ParryResolved.damageMultiplier`，由伤害与生命系统计算最终伤害、HP clamp 和死亡。
5. **短提前输入可缓存。** 输入在窗口开启前的允许缓冲范围内发生时，窗口开启后按 `window_open_timestamp_ms` 参与判定；原始时间只用于诊断。
6. **过早输入不消耗攻击段。** 超出 buffer 的过早输入产生 `ParryAttemptRejected(reason=TooEarly)`。
7. **取消、目标无效、场景过期不制造失败。** 这些情况走 `ParryCancelled` 或拒绝事件，不产生 `ParryResolved(FailedParry)`。
8. **不可弹反攻击不制造失败弹反。** `isParryable=false` 不打开窗口；若收到输入，则拒绝为 `Unparryable`。
9. **Perfect 必须改变节奏。** `PerfectParry` 按 `comboInterruptRule` 中断、暂停或继续后续段，并打开 counter 入口。
10. **正式 HUD 不显示精确窗口倒计时。** 读招主要来自敌人动画、攻击几何、音频蓄压和轻量视觉提示。

### States and Transitions


| State             | Entry Condition                 | Exit Condition                         | Behavior                                    |
| ----------------- | ------------------------------- | -------------------------------------- | ------------------------------------------- |
| `Idle`            | 无 active 可弹反段                   | 收到合法 `AttackSegmentTimelineSeed`       | 忽略弹反输入或记录 rejected                          |
| `Telegraphing`    | seed 通过基础校验并派生冻结时间轴             | 到达 `windowOpenMs` 或段取消                 | 记录攻击段、目标、时间轴版本，发布读招状态                       |
| `InputBuffered`   | 收到合法提前缓冲输入                      | 窗口开启后立即结算或段取消                          | 保存一次待判定输入                                   |
| `ParryWindowOpen` | `CombatClockMs >= windowOpenMs` | 收到有效输入或窗口关闭                            | 监听一次 `ParryAttempt`                         |
| `Resolving`       | 输入命中或窗口关闭                       | `ParryResolved` / reject / cancel 广播完成 | 计算 grade、offset、damageMultiplier、echoIntent |
| `Recovery`        | 当前段结果已消费                        | 攻击段恢复结束                                | 清理窗口，拒绝重复输入                                 |
| `Suspended`       | 暂停、hit stop、后台或系统菜单             | 恢复或段取消                                 | 不接收新输入；不重算已结算结果                             |
| `Cancelled`       | 攻击取消、目标无效、场景切换                  | 清理完成                                   | 丢弃未结算输入，不发失败、不发奖励                           |

## Implementation Contract

### Authoritative Time Source

所有判定时间必须来自同一个单调逻辑战斗时钟 `CombatClockMs`。弹反系统只读取 `ICombatClock.NowMs`，不得推进全局战斗时间。

输入系统负责 `TouchTimestampAdapter`：

`normalizedRawRealtimeMs = NormalizeRawTimestamp(rawTimestampMs, timestampOrigin, calibrationSample)`

`bridgeDelayMs = max(0, unityReceivedRealtimeMs - normalizedRawRealtimeMs - calibratedBridgeOffsetMs)`

`battleTimestampMs = max(0, CombatClock.NowMs - bridgeDelayMs)`

`latency_compensation_ms` 不得再次补偿 bridge delay。它只代表设备触控硬件、显示和玩家体感校准；实现必须同时记录 `bridgeDelayMs` 与 `latency_compensation_ms`，避免双重扣减。窗口已开启后的补偿结果不得早于 `window_open_timestamp_ms`。

### Runtime Layering


| Layer                | Owns                                                                               |
| -------------------- | ---------------------------------------------------------------------------------- |
| `game.gameplay` 纯 C# | 判定公式、状态机、`AttackSegmentTimelineSeed`、`FrozenAttackSegmentTimeline`、DTO、测试假时钟、事件记录器 |
| Unity 热更侧            | UGUI `ParryTouchArea`、Touch / Pointer 适配、VFX/SFX、震动、相机反馈、微信小游戏输入桥                  |
| Launch / AOT         | 热更加载与平台初始化，不承载弹反业务逻辑                                                               |


DTO 不得依赖 `UnityEngine.Vector2`。屏幕位置使用 `{ xDp, yDp }` 或项目纯数学类型；所有 ID 使用稳定 gameplay id，不使用 Unity instance id 作为持久事件键。

### Attack Segment Timeline

攻击模式提交 `AttackSegmentTimelineSeed`；弹反系统根据 seed 和 `window_profile` 派生 `FrozenAttackSegmentTimeline`。若派生结果违反不变量，弹反系统拒绝该 seed 并广播 `AttackSegmentTimelineRejected`。

`AttackSegmentTimelineSeed`:


| Field                             | Type        | Required | Description                                                          |
| --------------------------------- | ----------- | -------- | -------------------------------------------------------------------- |
| `sceneContextId` / `sceneVersion` | id/int      | Yes      | 场景过滤                                                                 |
| `battleContextId`                 | id          | Yes      | 所属战斗                                                                 |
| `attackSegmentId`                 | string/int  | Yes      | 当前攻击段唯一 ID                                                           |
| `timelineSequenceId`              | int         | Yes      | 时间轴版本，首个为 1，同段重排递增                                                   |
| `attackPatternId`                 | string/int  | Yes      | 攻击模式 ID                                                              |
| `attackerId` / `defenderId`       | string/int  | Yes      | 攻防双方                                                                 |
| `comboIndex`                      | int         | Yes      | 连击段序号，从 0 开始                                                         |
| `profileId`                       | enum/string | Yes      | 弹反窗口配置                                                               |
| `isParryable`                     | bool        | Yes      | 是否允许弹反                                                               |
| `nonParryableReason`              | enum        | If false | `None / BossRule / ScriptedUnparryable`                              |
| `windupStartMs`                   | long        | Yes      | 前摇开始                                                                 |
| `visualImpactMs`                  | long        | Yes      | 表现命中点                                                                |
| `damageCommitMs`                  | long        | Yes      | 伤害提交点                                                                |
| `recoveryEndMs`                   | long        | Yes      | 攻击段结束                                                                |
| `comboInterruptRule`              | enum        | Yes      | `InterruptOnPerfect / CounterInsertOnPerfect / ContinueAfterPerfect` |


`FrozenAttackSegmentTimeline` adds:


| Field            | Formula / Description                      |
| ---------------- | ------------------------------------------ |
| `parryCenterMs`  | `damageCommitMs - center_before_impact_ms` |
| `windowOpenMs`   | `parryCenterMs - normal_early_window_ms`   |
| `perfectStartMs` | `parryCenterMs - perfect_half_window_ms`   |
| `perfectEndMs`   | `parryCenterMs + perfect_half_window_ms`   |
| `normalEndMs`    | `parryCenterMs + normal_late_window_ms`    |


Timeline invariants:

- `windupStartMs <= windowOpenMs <= perfectStartMs <= parryCenterMs <= perfectEndMs <= visualImpactMs <= normalEndMs <= damageCommitMs <= recoveryEndMs`
- `perfect_half_window_ms <= normal_early_window_ms`
- `perfect_half_window_ms <= normal_late_window_ms`
- `center_before_impact_ms >= normal_late_window_ms`
- `windupStartMs >= 0` and all derived timestamps are `>= 0`

## Formulas

### Effective Input Timestamp

`effective_input_timestamp_ms = window_open_timestamp_ms if buffered_input_valid else max(window_open_timestamp_ms, battle_input_timestamp_ms - latency_compensation_ms)`

Output range: `>= window_open_timestamp_ms` when window is already open or buffered input is consumed.

### Timing Offset

`timing_offset_ms = effective_input_timestamp_ms - parryCenterMs`

`PerfectParry` when `abs(timing_offset_ms) <= perfect_half_window_ms`.

`NormalParry` when `windowOpenMs <= effective_input_timestamp_ms <= normalEndMs` and not Perfect.

`FailedParry` when no valid input is consumed before `normalEndMs`, or input is too late but still bound to the current segment.

### Damage Multiplier

`damage_multiplier = 0.0 if grade == PerfectParry; 0.5 if grade == NormalParry; 1.0 if grade == FailedParry`

### Counter Window

`counter_expires_at_ms = CombatClock.NowMs + counter_window_ms`

Counter window is valid only while battle context, scene context, attack segment id, timeline sequence id, and source `resolutionId` remain current.

## Edge Cases

- **If 场景上下文过期**: 拒绝事件，不改变当前战斗。
- **If 攻击段取消**: 广播 `ParryCancelled`，不制造失败。
- **If 目标 `CanReceiveDamage=false`**: 取消或拒绝，不制造 `FailedParry`。
- **If 输入发生在暂停中**: 输入系统应拒绝；弹反系统不缓存暂停期间输入。
- **If hit stop 期间重复触摸**: 已结算段不接受新输入。
- **If low FPS 跨过窗口边界**: 使用输入事件映射时间，不使用处理帧时间。
- **If 第二个可弹反段重叠**: 广播 `OverlapRejected`，后进入段重排或取消。
- **If `AttackSegmentTimelineSeed` 缺少字段或违反不变量**: 广播 `AttackSegmentTimelineRejected`，不进入判定。
- **If counter area 打开**: 弹反触区释放 raycast，不得吞掉 counter 输入。

| `ParryCancelled`              | 清理读招 cue              | cue fade out   | Medium   |
| `CounterEntryOpened`          | Counter 入口高亮          | 上扬 cue         | Critical |


## UI Requirements

正式 HUD 显示弹反触区状态、最近结果和 counter 可用态，但不显示精确倒计时、QTE 圈或“现在按”提示。开发构建可显示 `CombatClockMs`、`attackSegmentId`、`timelineSequenceId`、窗口边界和 `timingOffsetMs`。

Counter 打开时：

- `Counter` 触区优先级高于 `Parry` 触区。
- 弹反触区不得 `blocksUnderlying=true`。
- UI 更新触区必须递增 `stateVersion`，迟到输入按旧版本拒绝。

## Acceptance Criteria

### Logic and Timing

- **GIVEN** 合法 `AttackSegmentTimelineSeed`，**WHEN** 弹反系统派生冻结时间轴，**THEN** 所有 timeline invariants 成立。
- **GIVEN** seed 违反 `center_before_impact_ms >= normal_late_window_ms`，**WHEN** 验证，**THEN** 广播 `AttackSegmentTimelineRejected`。
- **GIVEN** 输入命中 perfect window，**WHEN** 结算，**THEN** 产生 `ParryResolved(PerfectParry, damageMultiplier=0.0, echoIntent=High)`。
- **GIVEN** 输入命中 normal window 且非 perfect，**WHEN** 结算，**THEN** 产生 `ParryResolved(NormalParry, damageMultiplier=0.5, echoIntent=None)`。
- **GIVEN** 窗口关闭且无输入，**WHEN** 结算，**THEN** 产生 `ParryResolved(FailedParry, damageMultiplier=1.0, failureReason=NoInput)`。
- **GIVEN** 输入早于 buffer 范围，**WHEN** 处理，**THEN** 产生 `ParryAttemptRejected(reason=TooEarly)` 且不消费攻击段结果。
- **GIVEN** 缓冲输入在合法范围内，**WHEN** 窗口开启，**THEN** 按 `window_open_timestamp_ms` 参与结算。

### Event and Ownership

- **GIVEN** `ParryResolved` 已为某段产生，**WHEN** 同段重复输入到达，**THEN** 产生 duplicate/rejected 事件，不重复伤害。
- **GIVEN** 攻击段取消或目标无效，**WHEN** 取消发生在结算前，**THEN** 产生 `ParryCancelled`，不制造 `FailedParry`。
- **GIVEN** 第二个可弹反段与 active 段重叠，**WHEN** 提交，**THEN** 产生 `OverlapRejected`。
- **GIVEN** `PerfectParry` 成立，**WHEN** counter 打开，**THEN** 广播 `CounterEntryOpened`，并携带来源 `resolutionId`、`attackSegmentId`、`timelineSequenceId`、`expiresAtMs`。
- **GIVEN** counter 被消耗、过期、取消或战斗结束，**WHEN** 关闭，**THEN** 回合管理器广播 `CounterEntryClosed` 且只广播一次。

### Integration

- **GIVEN** 输入系统标记 `timestampSource=ReceivedFrameFallback`，**WHEN** 弹反结算，**THEN** 结果仍使用 `battleTimestampMs`，并在证据中标记 fallback。
- **GIVEN** 战斗反馈请求 hit stop，**WHEN** hit stop 发生，**THEN** `CombatClockMs` 由回合管理器暂停，弹反系统不重算结果。
- **GIVEN** 场景卸载，**WHEN** 迟到 `ParryResolved` 到达，**THEN** 通过 `sceneContextId + sceneVersion` 拒绝。
- **GIVEN** 战斗 HUD 关闭 debug overlay，**WHEN** 敌人读招发生，**THEN** 玩家仍可通过敌人动画/音频完成时机判断。

### Device Evidence

- **GIVEN** 至少两台微信小游戏真机，**WHEN** 执行 30 次 perfect/normal/failed 边界测试，**THEN** 记录 `rawTimestampMs`、`receivedRealtimeMs`、`bridgeDelayMs`、`battleTimestampMs`、`latency_compensation_ms`、`timingOffsetMs`。
- **GIVEN** 15 / 20 / 30 FPS 低帧率环境，**WHEN** 注入边界输入，**THEN** 结果按输入时间戳而非处理帧时间判定。
- **GIVEN** 低端设备触发连续 Perfect 反馈，**WHEN** 战斗反馈降级，**THEN** 弹反结果和伤害倍率不变。
- **GIVEN** 不同安全区和屏幕比例设备，**WHEN** counter 打开，**THEN** counter 触区不被系统手势区遮挡且优先级高于 parry。
