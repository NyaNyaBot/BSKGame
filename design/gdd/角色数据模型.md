# 角色数据模型

> **Status**: Approved
> **Author**: Sulequan + Agents
> **Last Updated**: 2026-04-27
> **Implements Pillar**: 角色即动力；精准即快感；小而精致

## Summary

角色数据模型是《回响之刃》的战斗与成长数据地基。它定义玩家角色、敌人、Boss 和后续伙伴在战斗中的身份、基础属性、当前状态、队伍归属和可被其他系统读取的稳定快照，让回合管理、伤害、弹反、AI、技能、UI 和存档都引用同一套角色事实。

> **Quick reference** — Layer: `Foundation` · Priority: `MVP` · Key deps: `None`

## Overview

角色数据模型不是一个玩家直接操作的玩法按钮，而是所有角色相关系统的统一事实来源。每个参与战斗、探索或叙事状态判断的单位都必须有稳定的 `CharacterId`、阵营、角色类型、基础属性、当前生命、行动状态和可选标签。MVP 只需要支持 1 个可控角色、若干敌人和 1 个 Boss，但数据结构必须能自然扩展到 Vertical Slice 的三人小队、记忆碎片被动、角色对话条件和全员完美弹反。

## Player Fantasy

玩家不应该感到自己在操纵一堆临时数值，而是在守护一支真实的小队。角色数据模型通过稳定身份、清晰生命状态和可扩展的角色标签，让每次伤害、弹反、反击和未来的记忆碎片成长都能绑定到具体角色身上。它服务“角色即动力”：当玩家成功弹反时，系统知道是谁被保护、谁能反击、谁的状态因此改变。

## Detailed Design

### Core Rules

1. **每个角色必须有稳定身份。** 所有角色使用 `CharacterId` 作为跨系统引用键；战斗中不得用显示名、数组下标或 Unity instance id 作为长期引用。
2. **角色数据分为静态定义与运行时实例。** 静态定义描述角色原型；运行时实例描述当前 HP、状态、队伍、战斗可用性和临时修正。
3. **MVP 只支持基础战斗属性。** 必需属性为 `MaxHp`、`AttackPower`、`Defense`、`Speed`、`ParryAffinity`；不引入装备、等级、复杂元素抗性或属性克制。
4. **当前生命由角色实例持有，但伤害计算不在本系统完成。** 伤害与生命系统拥有伤害公式、HP 修改、死亡判定和死亡事件；角色数据模型只提供可读写字段和边界约束。
5. **角色状态必须可快照。** 回合管理器、弹反、UI、AI 和测试都读取不可变 `CharacterSnapshot`，避免同一帧内多个系统看到不同状态。
6. **阵营必须明确。** MVP 阵营为 `Player`、`Enemy`、`Neutral`；只有 `Player` 阵营且 `IsControllable=true` 的角色能接收玩家输入。
7. **角色可战斗性与可受击性分离。** `CanAct` 表示能否参与行动选择；`CanBeTargeted` 表示能否成为攻击目标；`CanReceiveDamage` 表示能否被伤害系统修改 HP。
8. **死亡不是删除。** HP 到 0 后角色进入 `Defeated`，保留 `CharacterId` 与快照，直到战斗流程或场景管理显式移除。
9. **MVP 不做永久成长写入。** 记忆碎片、被动能力和角色成长在后续系统中定义；本系统预留 modifier 通道，但 MVP 默认为空。
10. **所有跨系统修改必须有来源。** 对 HP、状态、临时修正的修改必须记录 `sourceSystem` 和 `reason`，用于 QA 和回放诊断。

### States and Transitions


| State           | Entry Condition        | Exit Condition                | Behavior              |
| --------------- | ---------------------- | ----------------------------- | --------------------- |
| `Uninitialized` | 角色定义存在但未生成运行时实例        | 创建 `CharacterRuntimeInstance` | 不参与任何战斗查询             |
| `Ready`         | 实例创建且 HP > 0           | 进入战斗或被禁用                      | 可被队伍、UI 和战斗流程读取       |
| `InBattle`      | 战斗开始并注册到战斗上下文          | 战斗结束、逃离、死亡或退场                 | 可被回合、伤害、弹反、AI、技能引用    |
| `Acting`        | 回合管理器授予行动或 AI 执行攻击     | 行动完成或取消                       | `CanAct=false` 防止重复行动 |
| `Defending`     | 敌方攻击目标锁定该角色，或弹反窗口绑定该角色 | 攻击段结束、取消或目标无效                 | 可触发弹反、防御、受击和 UI 聚焦    |
| `Defeated`      | 当前 HP <= 0 且死亡判定确认     | 战斗重置、复活或场景卸载                  | 不可行动，默认不可被普通攻击选为目标    |
| `Removed`       | 战斗流程或场景管理移除实例          | 新实例创建                         | 不再参与查询；历史事件仍可引用其 ID   |

### Data Contracts

`CharacterDefinition` 是静态配置，加载后不在战斗中修改：


| Field             | Type       | Required | Description                   |
| ----------------- | ---------- | -------- | ----------------------------- |
| `CharacterId`     | string/int | Yes      | 跨系统稳定 ID                      |
| `DisplayNameKey`  | string     | Yes      | 本地化显示名 key                    |
| `CharacterKind`   | enum       | Yes      | `Player / Enemy / Boss / NPC` |
| `DefaultFaction`  | enum       | Yes      | `Player / Enemy / Neutral`    |
| `BaseMaxHp`       | int        | Yes      | 基础最大生命，必须 `> 0`               |
| `BaseAttackPower` | int        | Yes      | 基础攻击力                         |
| `BaseDefense`     | int        | Yes      | 基础防御                          |
| `BaseSpeed`       | int        | Yes      | 基础速度或回合排序权重                   |
| `ParryAffinity`   | float      | Yes      | 弹反适性占位，MVP 默认 `1.0`           |
| `Tags`            | string[]   | No       | 角色、敌人类型、Boss、剧情等标签            |


`CharacterRuntimeInstance` 是战斗中可变实例：


| Field              | Type       | Owner        | Description      |
| ------------------ | ---------- | ------------ | ---------------- |
| `InstanceId`       | string/int | 角色数据模型       | 单次战斗实例 ID        |
| `CharacterId`      | string/int | 角色数据模型       | 指向静态定义           |
| `Faction`          | enum       | 回合 / 战斗流程    | 当前阵营，默认来自定义      |
| `RuntimeState`     | enum       | 回合 / 伤害 / 场景 | 当前状态             |
| `CurrentHp`        | int        | 伤害与生命系统      | 当前生命，写入时必须 clamp |
| `CanAct`           | bool       | 回合管理器        | 是否可被授予行动         |
| `CanBeTargeted`    | bool       | 回合 / 目标选择    | 是否可作为目标          |
| `CanReceiveDamage` | bool       | 伤害与生命系统      | 是否可被伤害修改 HP      |
| `IsControllable`   | bool       | 输入 / 回合流程    | 是否可绑定玩家输入        |
| `RuntimeTags`      | string[]   | 各系统追加        | 临时状态或战斗标签        |
| `Version`          | int        | 角色数据模型       | 每次可见状态变化递增       |


`CharacterSnapshot` 是下游系统读取的不可变视图：


| Field                                                              | Description      |
| ------------------------------------------------------------------ | ---------------- |
| `InstanceId` / `CharacterId`                                       | 角色引用键            |
| `Faction` / `CharacterKind`                                        | 阵营与类型            |
| `RuntimeState`                                                     | 当前运行状态           |
| `CurrentHp` / `EffectiveMaxHp`                                     | 生命显示与目标合法性       |
| `EffectiveAttackPower` / `EffectiveDefense` / `EffectiveSpeed`     | 下游公式输入           |
| `ParryAffinity`                                                    | 弹反相关系统的未来扩展输入    |
| `CanAct` / `CanBeTargeted` / `CanReceiveDamage` / `IsControllable` | 行为合法性标记          |
| `Tags` / `RuntimeTags`                                             | AI、技能、剧情、UI 条件   |
| `Version`                                                          | 快照版本，用于 UI 和测试断言 |


## Formulas

### Effective Stat

The `effective_stat` formula is defined as:

`effective_stat = clamp(base_stat + flat_modifier_sum, min_stat, max_stat)`

**Variables:**


| Variable | Symbol              | Type | Range          | Description             |
| -------- | ------------------- | ---- | -------------- | ----------------------- |
| 基础属性     | `base_stat`         | int  | `0-999`        | 来自角色静态定义                |
| 固定修正总和   | `flat_modifier_sum` | int  | `-999 to +999` | 临时状态或后续成长系统提供；MVP 默认为 0 |
| 属性下限     | `min_stat`          | int  | `0-1`          | HP 上限至少为 1，其他非负属性至少为 0  |
| 属性上限     | `max_stat`          | int  | `1-999`        | MVP 安全上限，防止配置错误         |


**Output Range:** `min_stat` 到 `max_stat`。  
**Example:** `base AttackPower = 20`，`flat_modifier_sum = 5`，输出 `25`。

### Current HP Clamp

The `current_hp_clamp` formula is defined as:

`current_hp = clamp(requested_hp, 0, effective_max_hp)`

**Variables:**


| Variable | Symbol             | Type | Range            | Description                  |
| -------- | ------------------ | ---- | ---------------- | ---------------------------- |
| 请求生命值    | `requested_hp`     | int  | `-9999 to +9999` | 伤害、治疗或初始化请求写入值               |
| 有效最大生命   | `effective_max_hp` | int  | `1-999`          | 由 `effective_stat(MaxHp)` 得到 |
| 当前生命     | `current_hp`       | int  | `0-999`          | 写回角色实例的生命值                   |


**Output Range:** `0` 到 `effective_max_hp`。  
**Example:** `effective_max_hp = 120`，伤害请求后 `requested_hp = -10`，则 `current_hp = 0`。

### Is Battle Eligible

The `is_battle_eligible` formula is defined as:

`is_battle_eligible = runtime_state != Removed && current_hp > 0 && can_be_targeted`

**Variables:**


| Variable | Symbol            | Type | Range                                                        | Description    |
| -------- | ----------------- | ---- | ------------------------------------------------------------ | -------------- |
| 运行时状态    | `runtime_state`   | enum | `Ready / InBattle / Acting / Defending / Defeated / Removed` | 当前角色实例状态       |
| 当前生命     | `current_hp`      | int  | `0-999`                                                      | 当前 HP          |
| 可被选为目标   | `can_be_targeted` | bool | `true/false`                                                 | 战斗规则、退场或状态效果控制 |


**Output Range:** `true` 或 `false`。  
**Example:** HP 为 0 的角色即使还在战斗上下文中，`is_battle_eligible=false`。

## Edge Cases

- **If 静态定义缺少 `CharacterId`**: 该角色定义无效，不能生成运行时实例。
- **If 两个角色定义使用相同 `CharacterId`**: 构建或加载阶段失败，必须修正数据。
- **If `MaxHp <= 0`**: 加载阶段将该定义标记为配置错误；MVP 不自动修正为 1。
- **If 当前 HP 写入超过有效最大 HP**: 通过 `current_hp_clamp` 截断到 `effective_max_hp`。
- **If 当前 HP 写入低于 0**: 通过 `current_hp_clamp` 截断为 0，并等待伤害与生命系统触发死亡判定。
- **If 角色已 `Defeated` 但仍收到输入**: 输入系统必须拒绝该输入并记录 `CharacterNotControllable`。
- **If 角色已 `Removed` 但迟到事件引用它**: 查询返回 historical stub 或 null；不得重新激活该实例。
- **If 一个系统试图直接删除角色以表示死亡**: 拒绝；死亡必须先进入 `Defeated`，由战斗流程决定何时 `Removed`。
- **If modifier 让属性低于下限或高于上限**: 使用 clamp 后的有效属性，并记录配置诊断。
- **If MVP 单角色场景需要未来三人扩展**: 数据结构仍使用队伍集合和 `CharacterId`，不得把玩家角色硬编码成 singleton。

## Tuning Knobs


| Parameter                     | Current Value | Safe Range | Effect of Increase | Effect of Decrease |
| ----------------------------- | ------------- | ---------- | ------------------ | ------------------ |
| `base_max_hp.PlayerMvp`       | `120`         | `80-180`   | 玩家更能承受失败弹反         | 失败更惩罚，原型更脆         |
| `base_attack_power.PlayerMvp` | `20`          | `10-40`    | 战斗更快，反击价值更高        | 战斗更慢               |
| `base_defense.PlayerMvp`      | `5`           | `0-20`     | 普通伤害更低             | 失败更痛               |
| `base_speed.PlayerMvp`        | `10`          | `1-30`     | 更容易在回合顺序靠前         | 更容易后手              |
| `parry_affinity.PlayerMvp`    | `1.0`         | `0.8-1.2`  | 后续可让角色更擅长弹反        | 后续可让角色更难弹反         |
| `max_stat_cap.Mvp`            | `999`         | `100-9999` | 允许更大数值空间           | 更早暴露配置膨胀           |


这些数值是原型占位，不代表最终平衡。正式战斗节奏应由伤害与生命系统、敌人攻击模式和战斗反馈一起回推。

## Visual/Audio Requirements

角色数据模型本身没有直接视觉或音频表现，但它必须向表现层提供稳定事件和快照，让其他系统播放正确反馈。


| Event                   | Visual Feedback            | Audio Feedback | Priority |
| ----------------------- | -------------------------- | -------------- | -------- |
| `CharacterRegistered`   | 调试面板可显示角色加入战斗上下文           | 无              | Low      |
| `CharacterStateChanged` | UI 可刷新状态图标、可控性、目标框         | 由具体状态系统决定      | Medium   |
| `CharacterHpChanged`    | 战斗 UI 更新 HP；受击/治疗表现由伤害系统触发 | 由伤害系统触发        | High     |
| `CharacterDefeated`     | 角色进入倒下/退场表现；具体动画由表现系统拥有    | 失败/倒下音效由反馈系统拥有 | High     |


## UI Requirements

角色数据模型不直接拥有 UI，但必须支持战斗 UI 查询以下信息：


| Information   | Display Location | Update Frequency       | Condition           |
| ------------- | ---------------- | ---------------------- | ------------------- |
| 当前 HP / 最大 HP | 战斗 HUD 角色状态区     | `CharacterHpChanged` 时 | 战斗中角色可见             |
| 行动状态          | 行动条、角色框或调试面板     | 状态变化时                  | 回合管理器更新             |
| 目标合法性         | 目标选择高亮、敌人选择框     | 目标选择时                  | 技能、AI、弹反目标查询        |
| 可控性           | 输入层调试 / HUD 状态   | 输入阶段或角色切换时             | `IsControllable` 变化 |
| 角色标签          | 调试面板             | 按需                     | QA 验证 AI、弹反、技能条件    |


## Acceptance Criteria

- **GIVEN** 一个角色静态定义包含唯一 `CharacterId`、基础属性和阵营，**WHEN** 创建运行时实例，**THEN** 生成稳定 `CharacterRuntimeInstance`，并可通过 `CharacterId` 查询。
- **GIVEN** 两个角色定义使用相同 `CharacterId`，**WHEN** 加载角色定义，**THEN** 加载失败并报告重复 ID。
- **GIVEN** `MaxHp <= 0` 的角色定义，**WHEN** 加载，**THEN** 该定义被标记为配置错误，不能进入战斗上下文。
- **GIVEN** 角色当前 HP 写入超过最大 HP，**WHEN** 应用写入，**THEN** `current_hp` 被 clamp 到 `effective_max_hp`。
- **GIVEN** 角色当前 HP 写入小于 0，**WHEN** 应用写入，**THEN** `current_hp=0`，且角色等待伤害与生命系统执行死亡判定。
- **GIVEN** 角色进入 `Defeated`，**WHEN** 输入系统尝试绑定玩家输入，**THEN** 输入被拒绝并记录 `CharacterNotControllable`。
- **GIVEN** 一个角色处于 `Removed`，**WHEN** 迟到战斗事件引用该 `CharacterId`，**THEN** 不重新激活实例，且事件记录为迟到引用。
- **GIVEN** MVP 场景只有一个玩家可控角色，**WHEN** 回合管理器请求玩家队伍列表，**THEN** 返回集合而不是 singleton，使三人扩展不需要改接口。
- **GIVEN** 实时弹反系统请求防守目标快照，**WHEN** 目标 `CanBeTargeted=false` 或 `CanReceiveDamage=false`，**THEN** 快照明确返回不可作为有效弹反防守目标。
- **GIVEN** 战斗 UI 订阅角色快照，**WHEN** HP 或状态改变，**THEN** UI 能通过事件或快照刷新，不直接读取可变内部对象。
- **GIVEN** 自动化测试创建 100 个角色实例并反复生成快照，**WHEN** 查询、状态切换和 HP clamp 执行，**THEN** 不出现重复 ID、负 HP、超过 MaxHp、状态非法跳转或集合污染。
