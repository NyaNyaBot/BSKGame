# 技能与行动系统

> **Status**: Approved
> **Author**: Sulequan + Agents
> **Last Updated**: 2026-04-27
> **Implements Pillar**: 精准即快感；角色即动力；小而精致

## Summary

技能与行动系统负责玩家在 `PlayerCommand` 阶段选择行动、在 `CounterWindow` 阶段执行反击，并把这些行动转化为结构化效果请求。MVP 不做完整技能树，只实现 `BasicAttackAction` 和 `CounterAction` 两条路径：前者验证回合制指令循环，后者验证完美弹反后的攻防节奏反转。

> **Quick reference** — Layer: `Feature` · Priority: `MVP` · Key deps: `回合管理器`, `角色数据模型`, `伤害与生命系统`, `实时弹反系统`, `输入系统`

## Overview

本系统不拥有回合阶段、不直接修改 HP、不决定弹反是否成功。它在回合管理器授予的输入窗口内接收玩家行动，校验角色和目标合法性，生成 `BattleActionRequest`，执行行动时间线，并向伤害与生命系统提交 `DamageRequest`。PerfectParry 打开的 counter window 是 MVP 的核心爽点：玩家可在短窗口内触发 `CounterAction`，对来源敌人造成高价值反击。

## Player Fantasy

玩家应该先在回合制指令里冷静出手，再在完美弹反后抓住一瞬反击机会。MVP 的行动选择不追求复杂菜单，而是让玩家理解两个关键承诺：我的常规攻击能推进战斗；我的完美弹反能夺回节奏并打出更强反击。

## Detailed Design

### Core Rules

1. **行动只能在合法输入阶段提交。** 普通行动只在 `BattleInputPhase=PlayerCommand`；反击只在 `BattleInputPhase=Counter`。
2. **MVP 只实现两个行动。** `BasicAttackAction` 和 `CounterAction`；技能槽、法力、冷却和连携技能延后。
3. **行动系统不直接写 HP。** 所有伤害通过 `DamageRequest` 交给伤害与生命系统。
4. **行动执行必须幂等。** 同一 `actionRequestId` 不得重复造成伤害或重复关闭 counter。
5. **目标合法性来自角色快照。** 不能攻击 `CurrentHp<=0`、`CanBeTargeted=false` 或场景过期目标。
6. **Counter 只能由 `CounterEntryOpened` 授权。** 不能因为 UI 按钮可见而自行创建 counter。
7. **Counter 消耗后必须关闭。** 成功执行或过期取消后通知回合管理器广播/确认 `CounterEntryClosed`。
8. **MVP 不实现失败行动延迟。** `FailedParry` 的行动惩罚延后；失败只通过伤害体现。
9. **行动时间线不得成为判定事实来源。** 动画时长可以影响表现完成，但伤害 commit 由行动配置和回合时钟事件明确触发。

### States and Transitions

| State | Entry Condition | Exit Condition | Behavior |
|---|---|---|---|
| `Idle` | 无行动窗口 | 输入阶段开启 | 不接收行动 |
| `AwaitingPlayerCommand` | `PlayerCommand` 输入阶段 | 合法行动提交或阶段关闭 | 显示/接受基础行动 |
| `ActionValidating` | 收到行动请求 | 通过或拒绝 | 校验 actor、target、phase、context |
| `ActionExecuting` | 行动合法 | 效果提交完成 | 播放/等待行动时间线，提交伤害请求 |
| `AwaitingCounter` | `CounterEntryOpened` | counter 提交、过期、取消 | 注册高优先级 counter 输入 |
| `CounterExecuting` | counter 合法 | 伤害提交并关闭 counter | 反击来源敌人 |
| `Cancelled` | 场景/战斗/目标过期 | 清理完成 | 不提交效果 |

## Formulas

### Action Base Damage

The `action_base_damage` formula is defined as:

`action_base_damage = round_half_up(actor_effective_attack_power * action_power_multiplier)`

**Variables:**
| Variable | Symbol | Type | Range | Description |
|---|---|---|---|---|
| 行动者攻击力 | `actor_effective_attack_power` | int | `0-999` | 角色快照 |
| 行动倍率 | `action_power_multiplier` | float | `0.1-5.0` | 行动定义 |

**Output Range:** `0-9999`。  
**Example:** 攻击力 20、Basic 倍率 1.0，基础伤害 20；Counter 倍率 1.5，基础伤害 30。

### Can Submit Action

The `can_submit_action` formula is defined as:

`can_submit_action = phase_matches && actor_can_act && target_valid && !action_duplicate && context_current`

**Variables:**
| Variable | Symbol | Type | Range | Description |
|---|---|---|---|---|
| 阶段匹配 | `phase_matches` | bool | `true/false` | 普通或 counter 阶段 |
| 行动者可行动 | `actor_can_act` | bool | `true/false` | 角色快照 |
| 目标合法 | `target_valid` | bool | `true/false` | 敌人可受击 |
| 重复行动 | `action_duplicate` | bool | `true/false` | 幂等缓存 |
| 上下文当前 | `context_current` | bool | `true/false` | scene/battle version |

**Output Range:** `true / false`。  
**Example:** Counter 阶段已过期，则 `phase_matches=false`，行动拒绝。

## Edge Cases

- **If 玩家在非 `PlayerCommand` 点击基础攻击**: 拒绝并记录 `ActionPhaseMismatch`。
- **If Counter window 已过期**: 拒绝 `CounterAction`，不得重新打开 counter。
- **If counter 目标已死亡**: 取消 counter 并关闭入口，不重定向到其他敌人。
- **If 同一 actionRequestId 重复提交**: 不重复造成伤害。
- **If 行动动画未播放完但伤害已 commit**: 伤害事实不回滚，表现可继续或取消。
- **If 场景卸载**: 取消 pending action，不提交新伤害。
- **If 玩家没有可用目标**: 基础攻击按钮禁用，回合管理器可进入错误/跳过处理。

## Tuning Knobs

| Parameter | Current Value | Safe Range | Effect of Increase | Effect of Decrease |
|---|---:|---:|---|---|
| `BasicAttack.powerMultiplier` | `1.0` | `0.5-2.0` | 普攻更强 | 战斗更慢 |
| `CounterAction.powerMultiplier` | `1.5` | `1.0-3.0` | Perfect 更有价值 | Counter 更克制 |
| `BasicAttack.commitDelayMs` | `250` | `0-600` | 表现更有重量 | 节奏更快 |
| `CounterAction.commitDelayMs` | `120` | `0-400` | 反击更戏剧化 | 反击更即时 |

## Visual/Audio Requirements

行动系统只提供事件和 cue id。反馈系统负责动画、打击、镜头和音效。

| Event | Visual Feedback | Audio Feedback | Priority |
|---|---|---|---|
| `ActionStarted(BasicAttack)` | 玩家攻击动作 | 攻击起手音 | High |
| `ActionCommitted` | 命中/伤害表现 | 命中音 | High |
| `CounterActionStarted` | 快速反击、敌人破绽 | 强反击 cue | Critical |
| `ActionRejected` | UI 禁用/轻提示 | 可选禁用音 | Low |

## Acceptance Criteria

- **GIVEN** 战斗处于 `PlayerCommand` 且玩家和目标合法，**WHEN** 玩家提交 `BasicAttackAction`，**THEN** 生成一次 `BattleActionRequest` 并提交对应 `DamageRequest`。
- **GIVEN** 战斗不在 `PlayerCommand`，**WHEN** 提交基础攻击，**THEN** 请求被拒绝且不造成伤害。
- **GIVEN** 收到 `CounterEntryOpened`，**WHEN** 玩家在窗口内提交 counter，**THEN** 执行 `CounterAction`，向来源敌人提交伤害，并关闭 counter。
- **GIVEN** Counter 已过期，**WHEN** 迟到输入到达，**THEN** `CounterAction` 被拒绝，不造成伤害。
- **GIVEN** 同一 `actionRequestId` 重复到达，**WHEN** 处理第二次，**THEN** 不重复提交 `DamageRequest`。
- **GIVEN** 目标在行动 commit 前死亡，**WHEN** 行动到达提交点，**THEN** 取消效果并记录 `TargetInvalid`。
- **GIVEN** 连续 100 次基础攻击与 counter 自动化测试，**WHEN** 固定输入和角色快照，**THEN** 行动事件顺序 deterministic，伤害请求数量正确。
